Scope: everything on `main` at commit `49eb111`. I read the domain rules, lock service, workers, data layer, every screen, the spec, DECISIONS, and the verification screenshots. I did not run the app; findings marked **verify** are strong suspicions from code reading, not reproduced failures.

Overall: the architecture is unusually clean for a v1 (pure-Kotlin rules, thin service, honest escape hatch, tamper *visibility* instead of an arms race). The product is not yet shippable to a real teen, mainly because (a) the lock has three zero-cost loopholes inside KEPT's own settings, (b) background reliability on Android 12–15 is unproven and probably broken for restarts, and (c) the buddy is a fake person.

## 1. What does not work (bugs and broken promises)

### Lock integrity

1. **Settings are a free unlock.** KEPT is in the hard allowlist, so during a lock window a teen can open Settings and, with zero friction or cost: (a) move the give-up time to "now", (b) delete the one undone habit, (c) add Instagram to Exceptions. All three take effect instantly (`LockRepository.observeState` recombines live). The 60-second break countdown becomes decorative. Fix: changes to lock window, habit removal, and exceptions made *during an active lock* either apply from tomorrow or go through the same break flow (cost a level, count against the cap).
2. **Deleting all habits disables the lock.** `habitsIncomplete = !allDone && total > 0`, so an empty habit list means never locked. Same fix as above.
3. **"Give-up time" copy contradicts the code.** Onboarding and Settings say "After the give-up time apps open again, and that day counts as missed." `RolloverEngine` only checks `habitsDone >= habitsTotal`; a habit finished at 23:30 still counts and still extends the streak. Either enforce the due time in the rollover (store `completedAt` vs due) or change the copy. The spec says "before the due time"; the code does not.
4. **Timer is honor-system and drifts.** `TimerController` counts `delay(1000)` ticks, not wall-clock time. In Doze the CPU sleeps, so a 30-minute exercise timer can read 24 minutes after 30 real minutes (the phone is in a pocket precisely when this habit runs). Use `SystemClock.elapsedRealtime()` deltas. Separately, nothing verifies exercise happened; the timer runs fine while the phone sits on a desk. Acceptable for MVP if the copy is honest about it.
5. **Timer runs while using exception apps.** Start "Exercise 30 min", then open Spotify or YouTube (if excepted). The timer keeps ticking. Consider pausing the timer whenever a non-KEPT app is foreground, or at minimum show "timer paused while you're in another app".

### Background reliability (the part that gets the app uninstalled)

6. **Watchdog cannot restart the service on Android 12+ (verify).** `WatchdogWorker` calls `ForegroundWatcherService.start(ctx)` from a plain periodic worker. Android 12+ throws `ForegroundServiceStartNotAllowedException` for FGS starts from the background; `runCatching` swallows it silently. So once the OEM kills the service (Samsung, Xiaomi, OnePlus do this routinely), nothing locks until the user opens KEPT. Worse, the watchdog then records a *protection gap* and the day is marked unprotected, so the kid is punished for the OS. Options: expedited work (`setExpedited`) which is exempt, an exact alarm (also exempt when it fires), or accept it and make "unprotected" softer (see 8).
7. **Heartbeat-based gap detection has false positives.** Heartbeat is written every 30 s only while the poll loop is awake. In deep Doze the loop does not run, the heartbeat goes stale, the 15-minute watchdog fires in a maintenance window, sees `age > 2 min`, and writes a `ProtectionGap`. The user did nothing wrong, the day cannot count, and the shield may be burned. This is the single most likely way a real streak dies unfairly. Compare heartbeat age against *screen-on time* (use `PowerManager.isInteractive` / `ACTION_SCREEN_ON` events), or only count a gap when a locked app was actually resumed during the gap.
8. **Heartbeat is written even when lock permissions are missing.** In `startPolling`, `prefs.heartbeat` runs outside `tick`, so the watchdog's "service was stopped" check never fires for a permission revoke; only the in-service detector does, and if the service dies while `gapStart != null` the gap is lost. Minor but inconsistent.
9. **Rollover recap after multi-day gaps.** Only the last day's summary is surfaced (`pendingRecapDate = last`). If a kid loses a 20-day streak on day 1 of a 3-day gap, the recap they see is day 3, which says "0 of 2" and nothing about the reset. Show the day the streak broke.

### Buddy

10. **Buddy cheer-after-break never fires.** `LockViewModel.breakLock` launches a 90 s delayed `simulateBuddyReaction("break")` + `revive()` in `viewModelScope`, then immediately calls `goHome()` which does `finishAndRemoveTask()`. The ViewModel is cleared and the coroutine cancelled. Sprig stays wilted, no cheer arrives. Move it to WorkManager or an app-scoped scope.
11. **Maya is fictional and the UI does not say so.** "Share with Maya", "Maya saw you finish", a 9-day streak and week grid, all seeded. A real teen pairing with a friend's code gets a stranger named Maya. Either hide the Buddy tab behind a debug flag until a backend exists, or label the state "Demo buddy" everywhere.
12. **Nudge/cheer notify *you*, not the buddy.** Expected given no backend, but the toast "Nudge sent" is a lie in a shipped build.

### Store / release blockers

13. **`applicationId = com.example.kept`.** Play rejects `com.example.*`. It is also hardcoded in `Allowlist.OWN_PACKAGE`, the README adb commands, and `scripts/verify.sh`.
14. **No release signing config, `isMinifyEnabled = false`, no CI.** Fine for a prototype; not for a build a tester installs.
15. **`fallbackToDestructiveMigration`** wipes streaks on the first schema change. Must go before any external tester installs a second build.
16. **Play policy declarations not prepared.** `QUERY_ALL_PACKAGES`, `PACKAGE_USAGE_STATS`, `SYSTEM_ALERT_WINDOW`, and `FOREGROUND_SERVICE_SPECIAL_USE` each need a declaration form with a video. App-lock / digital-wellbeing is an accepted use case, but expect a rejection cycle. No privacy policy URL exists yet either (required, even with zero network calls).

### Smaller correctness items

17. Lock screen clock (`LocalTime.now()` in composition) never ticks.
18. `Variants.forDate` is seeded by ISO week, so the reveal copy "only this week" is true, but two forms reached in the same week get identical variants; a Bud and Bloom both "Ember" look like duplicates in the gallery (visible in `11_gallery.png`).
19. Spec items not implemented: photo proof 7-day deletion, undo limited to 5 minutes (currently unlimited same-day undo, which also refunds a level via `Undone.wasAllDone`), recap thumbnail for photo habits.
20. Emergency button opens an empty dialer, not `tel:112`. Fine for policy, but the label "Emergency call" over-promises; "Phone" is more honest, or dial the local emergency number.

## 2. What needs more work or enhancement

### Mechanics that fight the goal

1. **Points reward procrastination.** 2 pts/min accrue while the lock is *active*, and the lock is active only while habits are undone. Finish your habits at 7:30 and you earn ~0 points; stall until 20:59 and earn ~1,600. Either accrue for the whole lock window regardless of completion (reward the day, not the wait), or drop time-points and keep only the habit bonus.
2. **Level is a second streak with no meaning.** "Bloom · Lv 13 · 2 days to Thicket" puts three numbers in one line. Level +1/day and −1/break is nearly identical to streak minus breaks, and nothing visual depends on it any more (sprout is now tied to form). Either make level *do* something (unlock accessories, colour saturation, Sprig size) or remove it and make the break cost the wilt plus a visible "−1 day toward next form".
3. **Default-deny will get uninstalled on day one.** Between 07:00 and 21:00 a teen's phone becomes phone+SMS+maps+camera. School apps, music, transit, bank, 2FA authenticator, group chats (WhatsApp is *not* the default SMS app) are all locked until they think to add exceptions. Onboarding step 3 asks them to guess. Ship a smart starter exception list (detect installed messaging, music, education, banking, authenticator categories) pre-ticked, and let them untick.
4. **Streak loss is too total for the audience.** 29-day Grove run → one missed day → back to "Sprig". The gallery softens it, but the displayed creature regressing to a baby is the moment kids quit. Common fix: a reset drops one *form*, not to zero, or costs half the streak. Keep it hard, not cruel.
5. **Shield UX.** The shield is auto-consumed at rollover with no choice. Teens like agency: "Use your shield on yesterday?" as a one-tap on the recap.
6. **Lock window is global; kids' days are not.** Sleep-by-11 as a MANUAL habit inside a 07:00–21:00 window makes no sense (you tap "done" at 22:30 when apps are already open). Either per-habit due times (the handoff data model had them) or a "wind-down" habit type that locks *after* a time rather than before.

### Sprig

7. **The forms barely differ.** Look at `15_roadmap.png`: Sprig, Bud, Bloom, Thicket, Grove are the same body with a 20-px head sprout swapped. A kid will not feel "evolution". Each form needs a silhouette change (size, ears, tail, wings, posture, eye shape), not a hat swap. This is the single biggest lever for retention and for shareable cards.
8. **No idle life.** Sprig has five static poses. Blink, breathe, look at the finger, react to a habit tap, a small celebratory bounce on completion. Compose `rememberInfiniteTransition` on the existing path renderer gets you 80% of the way.
9. **Evolution reveal is a screen, not a moment.** Needs a 2–3 second animation (old form → light → new form), haptics, and a "Share" button in that exact second when excitement peaks.
10. **Share card is generic.** 1080×1350 with form + streak. Add the kid's habit titles ("12 days of: guitar, run") so the card says something about *them*, not about the app.

### Screens

11. **Home hierarchy.** Sprig panel takes 40% of the screen; the actionable habits are below the fold on small phones. Consider Sprig at 60% of current height with the habits pulled up; make the lock-status line a live countdown ("locked for 3h 12m more" or "unlocked, done at 4:10 pm").
12. **Lock screen.** Good, but "12 minutes left to go" is ambiguous (timer left? lock left?). Say "12 min of exercise left". Also show the *blocked app's icon*; "Chrome is locked" as grey text does not register.
13. **Break screen.** Strong copy. Add a "What do you need it for?" chip row (Reply to someone / Look something up / Just bored) purely to create a pause and give the recap a tag; no data leaves the phone.
14. **Onboarding.** Five steps is long for a teen. Merge rule + exceptions, and move "Meet Sprig" to step 1 so the emotional hook comes before the permissions gauntlet. Show a 5-second "here is what a lock looks like" preview so the permission request is understood.
15. **Permissions step.** Four special-access toggles with system settings round-trips is the drop-off cliff. Add a per-card one-line "why" and an animated pointer to the exact toggle (OEM-specific screenshots for Samsung/Pixel cover 70% of devices).
16. **Empty states.** Fresh install shows "No habits yet" if you skip; good. But the gallery and buddy tabs on day 1 need a "day 3 unlocks Bud" carrot, not just faded cards.
17. **Dark theme exists but no screenshot verifies it.** Add it to `verify.sh`.

### Engineering

18. `AlarmReceiver` builds reminder copy with `"2 hours left"` hardcoded even though the minute is `max(due − 120, lockFrom + 30)`; wrong for short windows.
19. `WatchdogWorker` calls `buddy.tickDaily()` on `LocalStubBuddyRepository` directly, bypassing the interface; cleanup before a real implementation.
20. `LockActivity` is `singleInstance` with `taskAffinity=""` and starts from a service; test on Samsung One UI 6/7 and MIUI where BAL rules differ, and with a locked app in split-screen or PiP (PiP video from a locked app keeps playing).
21. No handling for time-zone change, DST, or the user setting the clock back (`pendingDates` has a 400-day guard only). A clock rollback past midnight re-runs nothing but also lets "today" be yesterday again with habits reset.
22. Instrumented tests run only on the API 35 emulator; add API 26 and API 30 to catch `queryEvents` and `MOVE_TO_FOREGROUND` differences.
23. Strings are all inline Kotlin; `strings.xml` has one entry. Fine for English-only v1, but every copy tweak now is a recompile and nothing is reviewable by a non-dev.

## 3. What is needed for MVP

Define MVP as: **20 real teens use it for 14 days, at least half still have it installed, and we learn whether the lock creates habits.** Everything below serves that; everything else waits.

### Must fix before the first external install

1. Close the three settings loopholes (§1.1–1.2): lock-window, habit removal, and exception changes apply tomorrow, or go through the break flow.
2. Fix timer to wall-clock (§1.4).
3. Fix protection-gap false positives (§1.7) or, until fixed, make an unprotected day *not* burn the streak; just show it hollow. Losing a streak to a bug is unrecoverable trust.
4. Service restart on Android 12+ (§1.6): expedited work or exact alarm, plus a persistent "Lock is off, tap to restart" notification when heartbeat is stale.
5. Buddy: hide the tab (feature flag) or label it "Demo". Do not ship Maya as a person.
6. Real `applicationId`, signed release build, Room migration strategy, privacy policy page.
7. Copy/behaviour agreement on the give-up time (§1.3).
8. Break cheer bug (§1.10) or remove the "buddy revives Sprig" promise from onboarding.

### Must have for the loop to work

9. **Starter exceptions** picked automatically by category (§2.3). Without this the first hour is rage.
10. **Distinct Sprig silhouettes** for at least Sprig → Bud → Bloom → Thicket (days 0–14, the MVP test window). Later forms can stay sketches.
11. **Completion moment**: confetti/bounce + haptic when the last habit finishes, and the notification "Apps are open. Promise kept." This exists in text; make it felt.
12. **A real reminder ladder**: morning "2 things today", due−2h (exists), due−30m. Keep it to three.
13. **Home widget or at least a persistent notification action** ("Start exercise", "Mark reading done") so completing does not require opening the app.
14. **Points either fixed or removed** (§2.1).

### Decide, do not build yet

15. Buddy backend. If the 14-day test shows retention without it, delay it. If kids ask "can my friend see this", that is the signal.
16. Per-habit lock windows.
17. Parent mode. Currently the teen is both the enforcer and the enforced; that is a real positioning choice (self-discipline app vs parental-control app) and it changes the marketing completely. Recommend staying self-imposed; it is the differentiator.

### Instrumentation for the test (local only, exported on request)

18. Log to a local file: locks shown per day, breaks, habit completion times, time-to-first-completion after lock start, uninstall proxy (last heartbeat). Add a Settings → "Export my data" that shares a JSON. Zero network, keeps the privacy promise, and you actually learn something from 20 testers.

## 4. Marketing page

There is no marketing page in the repo; the closest things are the README and the "Meet Sprig" onboarding step. Below is what I would build, written for a 13–17-year-old who found the link on a friend's story, not for a parent and not for a VC.

### Why the current framing is hard to understand

- "Keep Every Promise Today" is an acronym explanation, not a benefit. Kids do not decode acronyms.
- The README leads with mechanics (lock window, allowlist, rollover). Nobody wants a lock; they want the feeling of having done the thing.
- Three systems (streak, level, points, forms, shield, break cap) are all presented at once. Pick one hero mechanic for the page: **Sprig evolves when you do your stuff.**
- The word "habit" is a parent word. Teens say "do my stuff", "get it done", "actually practise".

### Positioning in one line

> **Your phone stays boring until you've done your thing. Then it's yours, and Sprig grows.**

Alternatives to test: "Do the thing. Unlock the phone. Level up the creature." / "The only app that locks *itself* out of your way once you've earned it."

### Page structure (single scroll, mobile-first)

1. **Hero.** Full-bleed animated Sprig (idle breathing, blinks) on the purple card. Headline above. One button: "Get KEPT" (Play link) and a smaller "See how it works (20 s)". No feature list here.
2. **The 20-second loop, as three phone frames side by side** (use the real screenshots, add motion):
   - "Pick 1–3 things you actually want to do." (onboarding habits)
   - "Until they're done, your phone is just a phone." (lock intercept with a recognisable app name)
   - "Finish. Everything opens. Sprig grows." (recap + evolution reveal)
3. **Meet Sprig.** Horizontal scroll of the eight forms with the day count under each, the way the onboarding shows it, but bigger and with the weekly looks cycling. Copy: "Every 3, 7, 14, 30 days Sprig changes. Each look is only available that week. Miss it, and it's gone."  Scarcity + collection is the teen hook; lead with it.
4. **"It's not your parents' app."** Three short cards:
   - "You set the rules. Nobody else can see anything." (no account, no tracking, no parent dashboard)
   - "You can always break the lock. It just costs Sprig." (show the 60-second countdown; honesty is a feature teens respect)
   - "Calls, texts, maps and camera always work." (safety, stated plainly)
5. **Buddy.** One frame: two Sprigs side by side. "Pick one friend. They see your streak, nothing else. Seven days together unlocks Duo, a form you can't get alone." Only include this section once the backend exists; otherwise cut it.
6. **Share cards.** A row of real generated cards (Bloom · Ember · 29 Aug, etc.) styled like story stickers. Copy: "Post the ones you earn."
7. **Proof / social.** After the 14-day test: three one-line quotes from testers with first name and age, plus a real number ("Testers finished their thing before 9 am on 71% of days"). Until then, skip this section rather than fake it.
8. **FAQ, five questions max.** Does it read my messages? (No; it only sees which app is in front, and never stores it.) Can I uninstall it? (Yes, any time; Sprig will be sad.) What if I need an app for school? (Add it as an exception; a few are pre-added.) Does it work on iPhone? (Not yet.) Is it free? (State the plan.)
9. **Footer CTA.** Sprig in wave pose. "Start today. Bud is three days away."

### Tone and craft notes

- Second person, present tense, short sentences. No "empower", "productivity", "wellbeing", "screen time".
- Show the lock screen with a *real* app name the audience uses (TikTok, Instagram, YouTube), not "Chrome".
- Sprig must move on the page. A static mascot reads as clip-art; a breathing one reads as a pet. The Compose renderer's path data can be exported to SVG and animated with CSS in an afternoon.
- Colour: keep the app's purple-on-cream; it is already distinctive and not "parental control blue".
- Name treatment: KEPT in caps, never explained in the hero. Put "Keep Every Promise Today" once, small, near the footer, as an Easter egg rather than a tagline.
- Put a 15-second vertical video (screen recording: lock → timer → done → evolve) at the top on mobile; it is the same asset you will need for the Play declarations and for stories.

### Copy bank (tested-tone drafts)

- "Your phone. After your stuff."
- "Lock in. Then unlock."
- "Three days gets you Bud. Seven gets you Bloom. Miss a day and you start over. Yeah, it's like that."
- "Break the lock any time. Sprig will remember."
- "No parents. No tracking. No feed. Just you and a small creature with high expectations."
