## How it was measured

Every `@Test` was read against the production code and the tests above it, in four slices. A
test went only if a named test at the same or a higher level asserts the same outcome, or if
the thing it guards no longer exists. Then the whole suite ran under JaCoCo before and after
(both with goldens rendering) and the reports were compared line by line. That comparison put
one test back: `HabitIconRules`' fallback icon had no other test.

What still differs after the change, all of it reviewed:

| Line | Why it is acceptable |
|---|---|
| `CelebrationCopy.spoken`, `OnboardingCopy.stepOf`, `WeeklyGoalDraft.iconKey`, `SprigLook.pose(onLockScreen)` | No caller in `app/src/main`. The tests were the only users. |
| `LockMode.of`, `ReminderActions.plan` (2 + 1 lines) | Default-argument stubs; production passes every argument. |
| One or two Compose-generated branches, different on each run | Recomposition bookkeeping, not app logic. |

Coverage says a line ran, not that it was asserted. The reading is what backs each removal;
the numbers only show nothing went dark.
